EV Evidence Vault

A chain-of-custody system for digital evidence — every file is fingerprinted and encrypted the moment it's uploaded, and every action anyone takes is written to a tamper-evident log that proves whether anything was ever altered.

🔒
Encrypted at restFiles are AES-256 encrypted before they ever touch disk. Only the app can decrypt them — never stored as plain files.

SHA-256 fingerprintedEvery upload is hashed on arrival. Verify integrity anytime to prove a file is still byte-for-byte identical to what was uploaded.
⛓
Tamper-evident audit logEvery action is chained to the one before it, like a mini blockchain. Edit any past record and the break is instantly detectable.

UploadYou upload a file to a case. It never leaves the server as plain data — it's read once, into memory only.

Fingerprint & encryptThe server computes a SHA-256 hash of the exact bytes, then encrypts them with AES-256-GCM before anything touches disk.
3
StoreThe encrypted file is saved on the server's disk. The hash, filename, and metadata are saved as a row in the database — never the plaintext.
4
LogThe action is appended to the audit chain — a new database row whose hash depends on the previous entry's hash, making silent edits detectable.

All of this runs on this server, backed by a real SQL database (H2 locally, or Postgres in production) — nothing is mocked or simulated.
